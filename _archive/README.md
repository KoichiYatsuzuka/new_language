# _archive — 役目を終えたスクリプト

**削除ではなく退避**。過去の実装ログ（[IMPLEMENTATION_LOG.md](../implementation_logs/IMPLEMENTATION_LOG.md)）が
これらを名指しで参照しているので、履歴を読むときに参照先が消えていない状態を保つ。

⚠ **現役のスクリプトはリポジトリ直下にある。** 何をいつ走らせるかは
[CLAUDE.md](../CLAUDE.md) の「Verification / measurement scripts」を見ること。

| ファイル | 何だったか | 退避した理由 | 代わりに使うもの |
|---|---|---|---|
| `run_examples.ps1` | 全例題を実行して pass/fail を数える素朴なランナー | **タイムアウトが無い**ので GUI・外部プロセス例題でハングする。`Start-Process -PassThru` の `ExitCode` を信じる作りでもある | **`scan_examples.ps1`**（タイムアウト付き・`System.Diagnostics.Process` を直接使う・失敗理由を 1 行で出す） |
| `bench.ps1` | **フェーズ 0**（バイトコード VM 移行前）のベースライン計測。「名前引き支配 vs `Value` クローン支配」を切り分ける判断ゲート用 | ⚠ **前提のツリーウォーク実行経路が #33 で削除された**。判断ゲート自体も通過済み。単一バイナリの計時なので A/B にも使えない | 速度課題を立てる前の分布取りは **`prof_dist.ps1`**、変更前後の比較は **`ab_bench.ps1`**（交互実行・負の対照つき） |
| `tw_stats_files.ps1` | `AR_TW_STATS` の**例題ごとの内訳**。ツリーウォークがどの例題に集中しているかを見るための補助 | ⚠ **その問いは決着した** — 現在 `in_fn` / `tw_control_flow` は**構造的に 0**（ツリーウォークが実行するのは定義文だけ）。集中先を探す必要がなくなった | 合計の内訳は **`tw_stats.ps1`**（0 でない値が出たら計測側の配線ミス） |

## ⚠ そのままでは動かないものがある

移動によって相対パスの基準が変わっている。**復活させるならパスを直すこと。**

| ファイル | 状態 |
|---|---|
| `bench.ps1` / `run_examples.ps1` | パスは**カレントディレクトリ基準**なので、**リポジトリ直下から** `./_archive/bench.ps1` のように呼べば動く |
| `tw_stats_files.ps1` | ⚠ `$PSScriptRoot` を 3 箇所で使っており、**`_archive/` を基準に `examples/` と `target/` を探してしまう**。動かすならそこを直す |

⚠ **復活させる前に前提が戻ったかを確かめること。** `bench.ps1` は「ツリーウォークがある」、
`tw_stats_files.ps1` は「ツリーウォークに文が残っている」ことを前提にしている。
