# コンパイル時メタ関数（`put` / `<! !>` / `^`）設計書

AST 展開時に**メタ関数**を実行し、クラス・関数・メンバ定義を生成する機構の設計書。
現行の実行時デコレータ（`@decorator`）を置き換える／補完する位置づけ。

- 対象: 新規サブシステム `src/meta_expand/`（予定）＋ lexer / parser / type_check / main の配線

- 状態: **仕様確定・実装未着手**（2026-09-19 に未決事項 D1〜D36 をすべて決着）
- **位置はシンボル名で指す**（関数名・`match` アーム名）。行番号は陳腐化するので書かない（`python_converter_fix_plan.md` と同方針）。
- **タスク番号は `<フェーズ>-<連番>`**（**0 始まり**。Phase 1 の 1 件目 = `1-0`）。§3 は**上から順に実行できる依存順**に並べてある。
- **必読部は 用語〜§4（上限 350 行）。** 超えたら根拠・実測を区切り線の下（参考）へ移す。

## 用語（2026-09-10 統一）

**「マクロ」とは呼ばない。「メタ関数」に統一する。**

| 用語 | 意味 |
|---|---|
| **メタ関数** | AST 展開時に実行される関数。宣言は **`exprconst fn`**（2026-09-10 決定） |
| **展開** | メタ関数を実行し、その返り値の AST をソースへ差し込むこと |
| **展開時** | 展開が走るフェーズ。parse の後・`resolve_and_annotate` の前（§0.1） |
| **展開時確定** | 値が展開時に定まること（形式的定義は D14 → 参考F） |
| **`put:` ブロック** | 中身を AST リテラルとして扱い、メタ関数の返り値に足すブロック（評価されない・§1.1）。⚠ **`put` は仮名**（→ D29）。**文形（`put 式`）は実装しない**（2026-09-10 決定） |
| **スプライス** | `<! !>` で囲んだ展開時の値を、その位置の構文へ変換して差し込むこと（§1.2） |
| **メタ情報演算子** | `^`。対象のメタ情報を得る前置演算子（§1.5）。⚠ `^^` は 2026-09-19 に**廃止**（D10） |
| **引数シグネチャ** | 仮引数列のメタ情報（D2） |
| **装飾子**（decorator） | メタ関数を定義に適用する構文および、そう適用されたメタ関数（→ D22） |
| **展開器** | 展開を行うサブシステム（`src/meta_expand/`・予定） |

⚠ 他言語の機構を指すときだけ「マクロ」を使う（Lisp マクロ、Rust の `macro_rules!` 等）。

## 0. 前提（着手前に必ず読む）

### 0.1 現行パイプライン

```
lex → parse（import はここで解決）→ resolve_and_annotate(&mut stmts) → wire_resolution → run
                                     ↑ 型検査 + slot 解決。配線は 1 箇所（`resolve_and_annotate` 呼び出し（src/main.rs））
```

メタ関数展開は **parse の後・`resolve_and_annotate` の前**に入る。→ §3.1。

### 0.2 既存の類似機構（これが土台になる）→ 参考H

**`alias 名前: 右辺` は既にコンパイル時 AST 置換**であり、**完全にパーサ内で完結**している
（＝wasm フロントエンドでも動く）。右辺を 1 回パースして保持し、定義自体は `Stmt::Pass` にして
AST から消し、参照位置で差し込む。ブロック境界でスコープを切る。実装の土台になる。
⚠ ただし **`node_id` ごとクローンしている**。この方針は継承しない（§0.3）。

### 0.3 `node_id` の制約（最重要）

`Expr::Ident { name, node_id, res }` の `node_id` は `Rc<Cell<u32>>` で**プログラム全体一意**に採番される。
`Parser::node_counter` の doc（`src/parser/mod.rs`） に「per-module 採番にしたら**別モジュールの注釈を読んでしまい、
FFI 境界検査で誤検知が実際に再現した**」と記録がある。

⇒ **展開器が生成する全ノードは同じカウンタから採番し、クローンしたノードは必ず再採番する。**
⇒ 併せて `res: Resolution` を `Unresolved` に戻す（注釈は最適化ヒントであって意味論の根拠ではない、の原則）。

### 0.4 字句の空き状況（実測）→ 参考H

`$`（数式文字列）と `#`（行コメント）は**使用済み**。`!`・バッククォート・`template` キーワード・
`put` は**空き**。`<!` / `!>` は**現在の Arrow で到達不能**（＝予約しても既存コードを壊さない）。

### 0.5 AST 上の格納形（スプライス先の実体）→ 参考H

型は **`Option<String>`**（`Param.type_ann` / `FnDef.return_type`）＝文字列なのでスプライスが安い。
`let`/`mut` は `Param.mutable: bool` / `FieldKind`、アクセス制御は**セクション方式**で
メンバ単位の構文が言語に無い。⚠ `InferredType::from_ann` は失敗を `None` で返し
**壊れた型文字列が黙って「型情報なし」になる** → スプライス時点で検証する（4-4）。

### 0.6 シグネチャは構文だけで確定する（実測・D15 の土台）→ 参考H

Arrow の関数まわりの型は**すべて注釈必須**で、推論なしに先行スキャンだけで揃う。**例外は無い**
（通常引数・戻り値・可変長・`gen` の産出型すべて必須。`self` は囲みクラスで既知。lambda は
言語に存在しない）。⇒ **`collect()` は推論なしに全シグネチャを確定できる。**

> **決定（2026-09-07）: 関数の引数の型注釈は必須を維持する。** ⚠ **この性質を壊す変更
> （引数注釈の任意化・lambda の導入など）は D15 を破壊する。**

### 0.7 型検査の現況（2026-09-09 実測）→ 参考J

別スレッド（[type_binding_enforcement_plan.md](type_binding_enforcement_plan.md)）の 0-1〜0-5 / 0-B2 で、**メソッド引数・コンストラクタ引数・戻り値・変数注釈**の
型検査が入った。`let b: float = 3` は `3.0` になり、無注釈 `let` の右辺推論も既に効く。
**未検査で残るのは「テンプレートクラスのコンストラクタ引数」と「既定値の型」の 2 つ**（修正中）。

## 1. 言語仕様（確定分）

> **この節に載せるのは、ユーザが明言した決定だけ。** 私（アシスタント）の導出・提案は
> §2 に置き、承認されるまで昇格させない。各項目に決定日を付す。

### 1.1 メタ関数の 2 種（2026-09-11）

```ar
exprconst fn  名前(仮引数...) -> Code:     # 純粋メタ関数。Code を返す。`return` を使う
exprconst !fn 名前(仮引数...) -> None:     # 配置メタ関数。`quote` で配置する
```

- 本体は **AST 展開時に実行される**。
- `!fn` は必ず `exprconst`。**`return` は使えない**。返り値を**値代入・式位置に置けない**。
  戻り値型は常に `None`（「値を返さない」ことの表明。`-> Code` の関数との見間違いを防ぐ）。
- **`quote` に到達せず抜けたらエラー**。何も出さないときは空 `Code` を `quote` する。

**呼び出し可能性（2026-09-19 確定）**

| 呼ぶ側 | `exprconst fn -> Code` | `exprconst !fn` |
|---|---|---|
| 通常コード | 不可（`Code` を持ち出せない） | **可**（文位置のみ） |
| `exprconst fn` | 可 | 不可（配置先が無い） |
| `exprconst !fn` | 可 | **不可** |

### 1.2 `Code` 型と `code:` ブロック（2026-09-11）

**型名は `Code`、ブロック導入語は `code`。**

- `code:` の中身は**行指向**で保持し、**その場ではパースしない**（未完断片を許すため）。
  パースは `quote` の 1 回だけ。
- **空の `Code`** は `code:` の直後にインデントを付けずに抜けて作る。
- **入れ子禁止**（`code:` の中に `code:` は書けない）。
- 演算: `+`（連結）/ `.indent()` / `.dedent()` / イテレート（1 行ずつ）。
- `.indent()` / `.dedent()` は**メソッド形**。後置呼び出しなので**連結より強く結合する**。
- インデントは**配置位置からの相対**。**0 未満になる行が生じる操作はエラー**。
- **`Code` はメタ関数の外へ持ち出せない**（型検査で束縛点を弾く）。

### 1.3 `quote` 文（2026-09-11）

`quote <Code 型の式>` — `Code` を AST に変換して**呼び出し位置へ配置**する。
**`quote` は関数を抜ける。** 以降の文は到達不能として診断する。

### 1.4 スプライス `<! ... !>`（2026-09-07 / 09-11）

`code:` の中で、展開時の値をその位置のトークン列へ変換して差し込む。

| 囲んだ値 | 変換先 |
|---|---|
| `str` | 識別子（変数名・関数名など） |
| 型 | 型名・型注釈 |
| 列（引数シグネチャ等） | カンマ区切りの並び |

⚠ **1 行に収まる値のみ。`Code` は入れられない**（複数行の合成は `+` と `.indent()`）。

### 1.5 メタ情報演算子 `^` とメタ情報型（2026-09-11 / 09-19）

- `^x` は対象のメタ情報を返す。**返る型は対象によって変わる**。
- ⚠ **`^^` は廃止**（2026-09-19・D10）。型側も `^` で引き、必要なら射影で辿る。
- **`^` を書けるのは、メタ関数呼び出しの実引数位置（通常コードでも可）とメタ関数の中だけ。**
  それ以外の通常コードでは書けない。
- メタ情報は**組み込み型**として用意する: `meta_instance` / `meta_function` /
  `meta_class` / `meta_member`。**フィールドとメソッドは別の型に分ける**。
- 各メタ情報型は **`.code()`** を持ち、元のコード内容を `Code` として返す。

```ar
mut x: Option[int] = None
my_meta_func(^x)          # ← `^` が現れるのはこの位置だけ
```

### 1.6 装飾子（decorator）（2026-09-11）

- **`!装飾子名`** を宣言の直前行に置く。対象が**第一引数**として渡る。
  対象はクラス宣言・関数宣言・クラスフィールド宣言・変数束縛。
- 装飾子には**クロージャ（メタ関数を束縛した変数）も書ける**。
- 入れ子は**内側から**展開する（関数と同じ）。
- ⚠ **`@` は実行時クロージャ装飾子として据え置き。** Arrow では `!` を使わせる。
  `@` に残る既存の欠陥（参考A #2〜#4）は**別件で修正する**。

### 1.7 展開の順序（2026-09-11）

**ファイル先頭から逐次に展開する。** 繰り返し（不動点）は行わない。

- ⇒ メタ関数・`^`・装飾子は**自分より前に宣言されたものだけ**を見られる。
- ⇒ 通常コードの前方参照は影響を受けない（レジストリの先行スキャンは展開後に走るため）。
- `const` は展開時に値が確定しているので**読める**。
- ⚠ **例外（D35 確定により有効）**: **テンプレート具体化サイトの収集だけは全体を事前走査する。**
  具体化は宣言より後ろに現れるため。⇒ 「宣言は前方のみ」の原則は保つが、**使用箇所の収集は別種の情報**として
  例外扱いする（→ 参考L）。

### 1.8 展開時の制御フロー（2026-09-07 / 09-11）

`if` / `for` に使えるのは**展開時に確定するものだけ**。
確定するもの: リテラル / メタ関数の仮引数 / メタ関数の返り値 / 展開済み `const`。

### 1.9 `!` の字句規則（2026-09-11）

`Token::Unknown('!')` を **`Token::Bang`** に格上げし、字句では `=` → `>` の順に判定する。

| 並び | トークン | 意味 |
|---|---|---|
| `!=` | `NotEq`（既存） | 不等号 |
| `!>` | `SpliceClose` | スプライス終了 |
| `<!` | `SpliceOpen` | スプライス開始（`<` 側で判定） |
| `!` + `fn` | `Bang` + `Fn` | 配置メタ関数の定義 |
| `!` + 識別子 | `Bang` + `Ident` | 装飾子の適用 |
| `!` 単独 | `Bang` | 上記以外はパースエラー |

### 1.10 関数の引数注釈（2026-09-07）

**関数の引数の型注釈は必須を維持する**（→ §0.6。展開時型推論 D15 の前提）。

## 参考 C. D11（変数注釈の禁止）を取り下げた経緯

**当時の動機（2026-09-07 実測）**: `let b: float = 3` が **`3`** を表示していた（注釈が値を float にしない）。

**⇒ 解消（2026-09-09 実測）**: 0-B2 の float 昇格＋0-1 の注釈照合により **`3.0`** になり、
`let s: str = 3` は `StaticTypeError` になった。**禁止する理由が無くなったため取り下げ。**
以下は「もし禁止していたら失われていたもの」の記録。

**しかし処方が広すぎる。** 禁止すると右辺だけでは決まらない 4 ケースで情報源が消える:

| # | ケース | 失われるもの |
|---|---|---|
| 1 | 空コレクション | `mut xs = []` の要素型。CLAUDE.md に「Empty collections require explicit typing」と明記された規則 |
| 2 | 数値の幅 | `UInt` と C ABI 型（`int8`/`int32`/`float32`…）。`let x = 5` からは導けず、**対応するリテラル記法が無ければ宣言不能になる** |
| 3 | トレイト／プロトコルへの拡大 | `let d: Drawable = circle` が具体型 `Circle` になり、見えるメソッドとオーバーロード解決が変わる |
| 4 | `Option` / `Union` | `mut o = None` は `None` 型。注釈が「あとで int が入る」情報を運んでいる |

**代替案**: 注釈を禁止するのではなく、**注釈とリテラルの不一致をエラー化**する
（`let b: float = 3` を通さず `3.0` を要求）。動機を満たしつつ 1〜4 を保てる。

## 参考 E. スプライス区切り `<! ... !>` の字句（D13 の入力）

**`<!` と `!>` は現在の Arrow で到達不能**（`!` 単独は `Token::Unknown('!')` で、`a ! 2` /
`a !> 2` / `<!a!>` はいずれも ParseError＝実測）。⇒ **予約しても既存コードを壊さない。**

**開き `<!` は無条件に安全。** `<` が結合するのは `<` / `=` / `-` の 3 つだけ
（`lexer/symbol.rs` の `'<'` / `'>'` 分岐）で `!` は含まれない。
⇒ 旧 `<...>` 案の開き側の衝突（`<-x>` が `LeftArrow`、`<<a>>` がシフト、`a < <b>`）は全て消える。

**閉じ `!>` は字句で取らないと危険。** `!` と `>` を別トークンのままにすると `>` が後続を貪欲に食う:

| 書き方 | 別トークンのまま | 2 文字トークンにした場合 |
|---|---|---|
| `<!name!>= 3` | `!` + **`>=`** ✗ | `SpliceClose` + `Eq` ✓ |
| `<!a!>>b` | `!` + **`>>`** ✗ | `SpliceClose` + `Gt` ✓ |

⇒ **`'<'+'!' → SpliceOpen` / `'!'+'>' → SpliceClose` の 2 規則で解決する。**
前案（パーサでのトークン分割）は不要になる。

**残る辺縁（軽微・空白で解決）**: `<!a!>>b` は `splice > b` になるので `>>` が欲しければ
`<!a!> >> b`。`a<<!b!>` は `<<` を先に取るので `a << <!b!>`。

**衝突しない点（実測）**: ①文頭の `<` は現在ありえない ②**比較の連鎖が無い**
（`a < b < c` は `ParseError`）＝ C++/Java 風ジェネリクスの曖昧性の主因が存在しない
③**型構文が `<`/`>` を使わない**（テンプレートは `[...]`。`parse_type_expr` に `Lt`/`Gt` 無し）。

## 参考 F. 「展開時確定」の形式的定義案（D14 の入力）

> 値 v が「展開時確定」であるとは、次のいずれか:
> 1. リテラル
> 2. メタ関数の仮引数
> 3. 展開時確定な値だけを引数とする、メタ関数または許可ビルトインの呼び出し結果
> 4. 展開時確定な値で初期化され、展開時確定な値しか代入されない局所変数
>
> `for` / `while` / `if` が「展開時に回る」とは、その反復対象／条件が展開時確定であること。
> それ以外の `for` / `while` / `if` は `put:` の中にしか書けない。

⇒ 展開時確定でない値が `put:` の外に現れたらエラーにする（黙って実行時にずらさない）。
⚠ `while` を許す以上、**展開ステップ予算と再帰深さ上限**が必須（2-6）。

```
進捗ゼロで未展開のメタ関数が残る → 循環エラー（関与する名前を列挙して報告）
```

各ラウンドは「展開するか止まるか」なので停止する。

⚠⚠ **`language-dev-principles` §1 の筆頭原則「注釈は最適化ヒントであって意味論の根拠ではない」
を反転させる。** 推論結果が「速さ」ではなく「どのコードが存在するか」を決めるため、現在 `Unresolved`
に落ちて「遅いが動く」に倒れている箇所が「**展開できない＝動かない**」になる。とくに合成 AST
（テンプレート実体化・展開結果）は `node_id: 0` / `Unresolved` のまま来るので、**メタ関数の生成物に
`^` を使うとまさにここに当たる**。⇒ 推論は**全域的かつ決定的**である必要がある。⇒ 着手前に 5-3。

### H.3 シグネチャ完全性の実測（§0.6 の根拠）

Arrow の関数まわりの型は**すべて注釈必須**で、推論なしに先行スキャンだけで揃う。**例外は無い**（実機確認）。

| 対象 | 強制 | 検出時点 |
|---|---|---|
| 通常の引数 | 必須 | `StaticTypeError: parameter '..' is missing a type annotation` |
| 戻り値 | 必須 | `StaticTypeError: function '..' is missing a return type annotation` |

| lambda | — | **言語に存在しない**（`Token::Lambda` は予約済み・パーサ未使用） |

### 機構 4 の状況（⚠ 2026-09-20 に更新。当初の結論は覆った）

当初は「Arrow に展開構文が無いので実行時 `@` では汎用ラッパを書けない。メタ関数が必須」と結論していたが、
**別スレッドが `f(*xs)` / `f(**d)` を実装した**ため、この前提は崩れた（→ 参考O）。
残る障害は `local::args` の静的型が `Option[list[T]]` であることだけで、これが直れば
`def w(*a, **k): return f(*a, **k)` 相当が**実行時デコレータだけで書ける**。
⇒ メタ関数はラッパ生成の**唯一の手段ではなくなった**（依然として有用ではある）。

### 機構 5 が代替不可である理由

`p.x` は実行時の操作で、アクセス箇所はプログラム中の任意の場所にある。生成器は自分が出力する
範囲しか書き換えられないので、**展開時評価を許容しても解決しない**。
依存しているもの: `@property` / `@x.setter` / `@cached_property` / 検証付き属性 / ORM のフィールド記述子。

### `@dataclass` の扱い（機構 2・3 の具体例）

Arrow の素のクラスが既に `__init__` 自動生成と**構造的等価**（`p == q` → True・実測）を持つので、
`@dataclass` は**変換器の修正だけで閉じる**。必要なのは 3 点:
①`dataclass` をマーカとして認識（現状は素通しされ実行時 `NameError`）
②クラス本体の**値なし注釈**（`x: int`）をフィールドへ変換（現状 `convert_class` の `AnnAssign` アーム（`src/python_converter/classes.rs`） は
`a.value` が `Some` のときだけ処理するので**黙って捨てている**）③`frozen=True` → `let` フィールド。
明示エラーにすべきもの: `repr=True`（自動 `__repr__` が無い）/ `order=True` / `field(default_factory=...)`
（`mut` フィールドに既定値を書けない）/ `ClassVar`。
