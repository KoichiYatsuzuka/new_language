# import の探索規則と可視性の修正計画（2026-10-02）

## 背景（利用者の報告）

1. サブディレクトリのファイルから上の階層のファイルを import できない
2. import したファイルの中で import されたファイルが、無条件に読めてしまう

## 決定した仕様（利用者の決定・2026-10-02）

- **上の階層は先頭のドットで指す**（Python の相対 import と同じ形）。
  `import ..util` / `from ..lib.helper import f` / `import .sibling`。
  `.` は import 文を書いたファイルのディレクトリ、ドットが 1 つ増えるごとに 1 つ上。
- **どの言語のファイルを import しても同じ規則で探す**（`.ar` / `.arc` / py / py-int / cpp / cs / js）。
- **エントリのディレクトリ（`root_dir`）からの探索は消す**。
- **再エクスポートしない**: モジュールの中の `import` / `from … import` で束縛した名前は、
  そのモジュールの名前空間に入れない（Arrow のモジュール）。
- import していないモジュールの型名（`util.Tag`）は、注釈・型テストで使えない。

規則の唯一の定義は [src/module_path.rs](../src/module_path.rs) の冒頭 doc。

## 判断の記録

- **モジュールの名前**はエントリのディレクトリからの相対パス（`pkg.util`）。エントリより上は
  `__parent__`（`__parent__.util`）。型の修飾名にも使うので各部分は識別子でなければならず、
  `..` は使えない。同じファイルはどの綴りで import しても同じ名前、違うファイルが同じ名前を
  取り合ったら明示エラー（`module_path::ModuleNames`）。
- **Python の外部の探索先**（`python.search_paths` / PYTHONPATH / site-packages）で見つけた
  モジュールの名前は書いた綴り（Python と同じ付け方）。ドット付きの書き方では外部を見ない。
- `import[rs]` はクレート名を取る（ファイルではない）ので相対の書き方は誤り。
  `ar_config.json` は import 文のファイルのディレクトリから祖先へ探す（他の設定と同じ）。
- 実行時の C# ブリッジ／ホスト探索にあった CWD への退避は外した（起点の規則に無い探索）。
- 1-6: `impl_python` の py import は `importlib` が失敗すると空の名前空間へ落ちる作りで、
  `sys.path` にソースのディレクトリが無かったため**ほぼ常に失敗していた**。起点を足したら
  import が成功するようになり、成功時に不変の束縛へ再代入して落ちる潜在バグが出たので直した。
  その結果 `compare_python_impl` の既知差分 9 件が一致するようになり、外した。
