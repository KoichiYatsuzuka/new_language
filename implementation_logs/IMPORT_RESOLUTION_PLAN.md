# import の探索規則と可視性の修正計画（2026-10-02）

## 背景（利用者の報告）

1. サブディレクトリのファイルから上の階層のファイルを import できない
2. import したファイルの中で import されたファイルが、無条件に読めてしまう

## 決定した仕様（利用者の決定・2026-10-02）

- **上の階層は先頭のドットで指す**（Python の相対 import と同じ形）。
  `import ..util` / `from ..lib.helper import f` / `import .sibling`。
  `.` は import 文を書いたファイルのディレクトリ、ドットが 1 つ増えるごとに 1 つ上。
- **どの言語のファイルを import しても同じ規則で探す**（`.ar` / `.arc` / py / py-int / cpp / cs / js）。
- **エントリのディレクトリ（`root_dir`）からの探索は消す**。
- **再エクスポートしない**: モジュールの中の `import` / `from … import` で束縛した名前は、
  そのモジュールの名前空間に入れない（Arrow のモジュール）。
- import していないモジュールの型名（`util.Tag`）は、注釈・型テストで使えない。

規則の唯一の定義は [src/module_path.rs](../src/module_path.rs) の冒頭 doc。

## 仕様変更（利用者の決定・2026-10-02 午後）— **モジュールの呼び出し方を CPython と同じにする**

フェーズ 1〜3 の後、利用者が「全面的に CPython 準拠」を選んだ。上の決定のうち次を**置き換える**（フェーズ 4）:

| 項目 | フェーズ 1〜3 | フェーズ 4（CPython 準拠） |
|---|---|---|
| ドット無しの `import a.b` の探索先 | 書いたファイルのディレクトリ → 外部 | **エントリのディレクトリ（`sys.path[0]` 相当）** → 外部（全言語）。書いたファイルのディレクトリは探さない（暗黙の相対 import は無い） |
| `import a.b`（`as` 無し）の束縛 | `b` | **`a`**（`a.b.f()` と呼ぶ）。`as m` なら `m = a.b` |
| パッケージ | `a/__init__.ar` は単独のモジュール | `import a.b` は `a` → `a.b` の順に読み込み、**サブモジュールが親の属性になる**（どこで import されても付く・`sys.modules` と同じ）。`__init__` の無いディレクトリは空の名前空間パッケージ |
| `from a import b` | `b` は a の名前だけ | a の名前に無ければ**サブモジュール a.b を読み込んで束縛** |
| 再エクスポート | しない（`ModuleHasNoMember` / `CannotImportName`） | **する**（モジュールの中の import 束縛も名前空間のメンバー）。本当に無い名前だけが誤り |
| 相対 import | `import ..x` / `from ..m import y` | 加えて **`from . import x` / `from .. import x`**。`import ..x` も残す（Arrow の拡張）。エントリのファイルからも、エントリより上へも使える（CPython は不可・不具合 1 の修正を保つため） |
| import していないモジュールの型名 | 誤り | 誤りのまま（CPython でも束縛されていない名前は `NameError`） |

⚠ 外部言語（cpp / cs / js / rs）のドット区切りはヘッダ・DLL・JS・クレートの**ファイルの場所**であって
パッケージ階層ではないので、束縛（別名か末尾・cpp はヘッダの stem）は変えない。探索先の規則だけ揃える。

## 判断の記録

- **モジュールの名前**はエントリのディレクトリからの相対パス（`pkg.util`）。エントリより上は
  `__parent__`（`__parent__.util`）。型の修飾名にも使うので各部分は識別子でなければならず、
  `..` は使えない。同じファイルはどの綴りで import しても同じ名前、違うファイルが同じ名前を
  取り合ったら明示エラー（`module_path::ModuleNames`）。
- **Python の外部の探索先**（`python.search_paths` / PYTHONPATH / site-packages）で見つけた
  モジュールの名前は書いた綴り（Python と同じ付け方）。ドット付きの書き方では外部を見ない。
- `import[rs]` はクレート名を取る（ファイルではない）ので相対の書き方は誤り。
  `ar_config.json` は import 文のファイルのディレクトリから祖先へ探す（他の設定と同じ）。
- 実行時の C# ブリッジ／ホスト探索にあった CWD への退避は外した（起点の規則に無い探索）。
- 4-2: パッケージの連鎖は**束縛しない `Stmt::Import`（`bind: None`）を元の文の手前に足す**形にした
  （`Parser::pending_stmts`）。実行時・型検査・型レジストリ・展開器が既存の import の経路でパッケージの
  本体も処理するので、各 walker に新しい欄を教えずに済む。束縛名は AST の `bind` 1 か所で決める
  （以前は 8 か所が「別名か末尾」を自分で計算していた）。
- 4-2: サブモジュールの表は名前空間の値ではなく `Interpreter::submodules` に持つ。値に持たせると親と子が
  互いを指す循環になり、非同期タスクへの深い複製が止まらない。タスクへは表ごと複製して渡す。
- 4-2: 型レジストリは修飾名の再エクスポートをたどる（`chase_reexport`）。`from wrapper import Item`
  （wrapper が core から取り込んだ Item）が存在しないクラス `wrapper.Item` にならないように。
- 4-2: 読み込み中のパッケージ（その `__init__` の中からの import）は連鎖に足さない。CPython と同じく
  初期化中のパッケージから自分のサブモジュールを読めるように（足すと循環 import の誤り）。
- 4-3: `__init__` の無い名前空間パッケージは本体が空なので、型検査の「読み込めていない import」
  （`has_unloaded_import`）に Arrow / py の空の本体を数えないようにした（数えると未定義名などの検査が止まる）。
- 1-6: `impl_python` の py import は `importlib` が失敗すると空の名前空間へ落ちる作りで、
  `sys.path` にソースのディレクトリが無かったため**ほぼ常に失敗していた**。起点を足したら
  import が成功するようになり、成功時に不変の束縛へ再代入して落ちる潜在バグが出たので直した。
  その結果 `compare_python_impl` の既知差分 9 件が一致するようになり、外した。
