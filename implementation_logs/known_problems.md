## #1 ガード付きのメソッド呼び出しの `float` の結果を箱に詰める

### 現象

型の注釈で受け手のクラスが分かるメソッド呼び出しは、実行時に `class_id` を照合するガード（`CB_METHOD_GUARD`・D-2）を
置き、通ればコンパイル済みの `_impl` を直接呼び、外れれば名前で呼ぶ（`emit_guarded_method_call`）。2 つの道の結果は
**ハンドル**（`alloca i64`）で合流する。直接呼んだ `_impl` が `double` を返しても `make_float` でハンドルに詰め直すので、
結果を使う演算も型の無い道（`binop` のコールバック）になる。

```
for b in self.bodies:      # b は list[Body] の要素 → ガード付き
    e += b.kinetic()       # kinetic は float を返す
```

ガードを通ったときの 1 回あたりのコールバック（`e += ...` の分）:

| 今 | 合流を `double` のままにした場合 |
|---|---|
| `make_float`（結果）・`make_float`（`e`）・`binop`・`to_float` の 4 回 | 0 回（`fadd`） |

`kinetic` の中の `0.5 * self.mass * self.vel.dot(self.vel)` も同じ形（`dot` がガード付き）。

⚠ `int` を返すメソッドは、合流の後に `to_int` で開けている（`gen_call_unwrapped`）。そのため `float` だけが型の無い道になる。

### 影響（2026-10-27・`b20f63b`）

合流を `double` のままにした実験の exe（外れた道の結果を `to_float` で開ける形・変更は捨てた）と、今の exe の A/B
（`speed_modes.ps1 -Modes native`・7 回の中央値）:

| 区間 | 今 | 実験 | 比 |
|---|---|---|---|
| k2 `list[Body]` の反復 | 0.517 s | 0.488 s | 1.059x |
| ほかの区間 | | | 0.970〜1.013x（ノイズの幅） |

`float` を返すメソッドをガード付きで呼び、その結果で計算するループだけに効く。k2 の遅さの主因はイテレータの寿命
（計画書 §0.6 要因 5・11-1）で、そちらを直せばコンパイル済みは VM より速くなる（実験で 0.377 s 対 0.476 s）。

### 直さない理由

1. 影響が小さい（上の 1.06x だけ）。
2. 直すには、**注釈が外れたときの値**の扱いを決める必要がある。ガードが外れるのは、受け手が注釈のクラスではないとき
   （`list[Body]` に別のクラスの値が入っているなど・注釈は意味論の根拠ではない・`language-dev-principles` §1）。そのとき名前で
   呼んだ別のクラスのメソッドは `float` 以外を返しうる。合流を `double` にすると次のようになる。
   - `int` を返したら `float` に広げてしまう（VM なら `int` のまま: `let x = b.kinetic()` の `str(x)` が `"3"` と `"3.0"` で違う）。
   - 数でない値を返したら `to_float` の `TypeError` になる（VM なら、その値で続きの演算をする）。

### 直すときの案

- **案 1**: 外れた道の結果が `Float` のときだけ `double` で合流する。それ以外のときは、その式の残りを型の無い道で
  計算する（合流の後を 2 通り生成する。生成コードが増える）。
- **案 2**: 外れた道で結果を開ける。`float` 以外ならエラーにして、`int` の合流（`to_int`）の扱いと合わせる。
  VM と値が違いうるので、規約（掬いきれなかった選択肢はエラーにする）の範囲で、静的に弾けるかを先に調べる。

### 関連（未確認）

`int` を返すメソッドの合流の `to_int`（`ar_to_int`）は、外れた道の結果が `float` なら切り捨て、`bool` なら 0 / 1 にする。
注釈が外れたときだけ通る道なので、VM と値が違いうる（例題では未確認）。#1 を直すときに同じ扱いを決める。
