## 2. 決まった言語仕様

### 2-a. 共有は `let → let` のときだけ（B8 / B9 / B11 / L1〜L6）

**参照を共有するのは `let` 変数から `let` 変数へ束縛するときだけ。それ以外は必ずディープコピー。**

⭐ この 1 文に集約するまでに、束縛の漏れを 6 つ塞いだ（L1〜L6）。**順序が規模を決めた**
—— 先に漏れを塞いだので、B8 は起票の見積もり（値レベルの可変フラグを約 200 箇所）ではなく
**型検査の静的検査だけ**で済んだ。

⚠⚠ **帰結: 循環した構造が作れなくなった**（L4）。格納もディープコピーになったので、
`a.append(a)` は「格納時点のスナップショット」を入れる（`[1, [1]]`）。
これは意図した仕様で、**B10 の起票が成立しなくなった**原因でもある。

- 速度: 格納する値のサイズに比例。プリミティブほぼ無料（+5%）／小インスタンス +21%／
  **8 要素のリストで 2.9 倍**。全体では `bench_container_insert` 0.836x。
- ⚠⚠ **`borrow_mut()` を握ったまま複製してはいけない**。値が対象自身を含むと
  `RefCell already mutably borrowed` でパニックする。実装中に **3 経路**で踏んだ。

### 2-b. 辞書のキーと等値（B1 / B2）

- キーは **`None` / `void` 等の「存在しないことを示す型」以外のあらゆる型**（部分型・`Any`・
  protocol・**型そのもの**を含む）。キーの内容は変更不可（`let` 属性）。
- 既定ハッシュ `default_hash` を全 `Value` に定義。**シードはプロセスごとにランダム化**。
  float は Python と同じアルゴリズム。
- 等値は**二層**:
  - `values_eq` … 「値の同一性」。**型に厳しい**（`1 == True` は偽）。
  - `values_eq_expr` … 「式としての比較」。数値の昇格を許す（`1 == 1.0` は左辺を昇格して真）。
- 深さ上限: キー 64 ／ `values_eq` 200（超えたら `RecursionError`）／ `default_hash` は**打ち切り**。
  ⚠ 複製だけは打ち切れない（値が壊れる）ので、この非対称は意図的。
- 実装: `IndexMap<HKey, Value>` ＋ `raw_entry_v1`（`Hash + Eq` 境界を要求しない）。

### 2-c. `for` のループ変数はブロック内の束縛（B4）

1. **外側に同名があれば再束縛としてエラー**（同一スコープ／関数の外側／モジュールグローバル／
   型検査のグローバル表に載る名前）。⚠ 新しい規則ではなく、**既存の再宣言規則を `for`
   ターゲットにも及ぼしただけ**。
2. **ブロックを抜けたら解放**。以降の読みは `NameError`。
3. **`let` / `mut` は反復対象の属性を継ぐ**。`range(n)` のような一時値は `let`。

⚠ `for` 文と `for` 式（＝内包表記の脱糖先）に**同じく適用**する。片方だけ直すと内包表記が
黙って古い規則のまま残る（実装中に 2 回踏んだ）。

⚠ 規則 1 の副産物として「for ターゲットに覆われたグローバルを `GlobalRef` にしてはいけない」
（#21-b の罠）が**構成不能**になり、`shadowed_for_targets` 機構を撤去できた。

⚠ CPython との**意図した違い**: `for i in xs: pass` のあとで `i` を読む形はエラーになる。
値が黙って食い違うのではなく明示エラーで、どちらも避けるべき書き方なので止めるのが正しい。

### 2-d. ジェネレータはコルーチン（B13）

**`yield` で本体を中断し、消費のたびに次の `yield` まで再開する**（CPython と同じ設計）。

- 無限ジェネレータが書ける。生成と消費が交互になる。消費しなければ本体は 1 行も走らない。
- **`yield` は `gen` 本体の直下だけ**。⚠ 体裁ではなく**設計の前提** —— `yield` が自分の
  フレームにしか現れないから「中断＝ディスパッチループを 1 回抜けるだけ」で済む。
- 取り出し済みの値は**捨てる**（one-shot・メモリ一定）。
- `finally` が走る条件:

  | 形 | `finally` |
  |---|---|
  | 消費し切った／`close()` を呼んだ | ✅ その場 |
  | 変数に持ったままプログラム終了 | ✅ 終了時スイープ |
  | 途中で捨てた | ❌ 走らない（Python との既知の差）|

  ⚠⚠ **Rust の `Drop` から Arrow のコードは呼べない**（`&mut Interpreter` を持てず、
  エラーも返せず、VM が借用中に再入する危険がある）。これが最後の 1 行の理由。

### 2-e. スタック枯渇でプロセスを落とさない（B10）

- **チャンク実行の入れ子に上限**（`MAX_CALL_DEPTH = 1000`、CPython と同じ）→ catchable な
  `RecursionError`。⚠ **`vm::run` で数える**（関数呼び出し側ではない）—— ジェネレータ本体は
  `exec_fn_evaled` を通らないので、関数側だけ守っても再帰するジェネレータが落ちたままになる。
- インタプリタを **64MB の専用スタックのスレッド**で走らせる。
  ⚠⚠ **定数とスタックサイズは対**。スタックを広げずに定数だけ上げると abort に戻る。

  | スタック | 満ちる深さ |
  |---|---|
  | 1MB（main の既定）| ~134 |
  | 64MB（現行）| ~9000 |

## 3. 系統別の要点

### B1 / B2（辞書と等値）
`Value` 全種に `default_hash` を定義し、辞書を `IndexMap<HKey, Value>` へ差し替えた。
`HKey { hash, key }` を持ち `raw_entry` で引くので、`Hash + Eq` を実装できない `Value` でも
キーにできる。`__eq__` / `__hash__` のユーザ定義はオーバーライドとして効く。

### B3 / B7（キャプチャまわり）
どちらも**キャプチャ解析ではなく別の場所**が原因だった。B3 は「`mut` パラメータのセルに
引数が流れ込んでいなかった」（引数は slot に置かれ、セルは `None` のまま）。
B7 は自由変数の定義が 2 箇所にあったので `fn_own_names` 1 箇所へ寄せた。

### B5 / B6（機能の欠落）
B5 は `list + list` / `list * int` の実装。B6 は**モジュール本体からの自己呼び出し**で、
`emit_callee_load` を入れた。⚠ **最上位ホットループで最大 5.7% の速度回帰を承知で採った**
（回収は `#11 グローバル領域の索引化`。消費者が現れたことを FUTURE_FEATURE.md に記録し、保留）。

### B12 / B13（ジェネレータ）
B12 は `GENERATOR_YIELDS`（yield 収集バッファ）が**入れ子にならない単一のスロット**だったこと。
外側が走っている最中に内側を**作るだけ**で上書きされ、以降の `yield` が黙って捨てられた。
B13 はその先行評価そのものをやめてコルーチン化した（段階 0〜E の 6 コミット）。

## 4. ⚠⚠ 起票の見立てが外れた 5 件

**起票時の原因の見当は当てにならない。最小形での切り分けのほうが速く正確だった。**

| # | 起票の見立て | 実際 |
|---|---|---|
| B3 | `capture_env` と `nested_fn_captures` の事前解析漏れ | **セルの初期化**。事前解析は正しく動いていた |
| B8 | 値レベルの可変フラグを**約 200 箇所** | L1〜L6 を先に塞いだので**型検査の静的検査だけ**で済んだ |
| B10 | 循環した値の複製 | L4 で**循環が作れなくなり再現手順が消滅**。真の問題は「深さ 130 で素の再帰が死ぬ」 |
| B12 | 再帰ジェネレータが壊れる | **再帰は無関係**。ジェネレータの中でジェネレータを**作る**形すべて |
| B13 | 二重ループ（`run_dispatch` / `run_stepping`）で片方だけ直すと黙ってずれる | **外れ**。両方の `match` が網羅的で**コンパイラが 2 箇所とも止める** |

⚠ B13 の最後の 1 件は**私が事前に「最大のリスク」と主張したもの**で、`Flow` に variant を
足す実験で反証された。**リスクの主張も実験で確かめる。**

⚠ 逆に、**ソースのコメントが的中した**例もある。`nested_fn_free_names` の `P::GenBody` は
空で「拾うなら `gen` の VM 対応と同時にやれ」と書いてあり、その通りだった（埋めるまで
可変キャプチャを持つ入れ子 `gen` が bail し続けた）。

## 5. ⚠⚠ 測り方を間違えた 2 件

### 5-a. A/B ベンチで「片方だけコピー」した

段階 B 以降ずっと「A＝使い回しの旧バイナリ／B＝新規コピー」で測っており、
**Windows Defender の新規ファイル走査が B 側にだけ乗っていた**。変種を 5 つ試して
**すべて一貫して「2〜8% 遅い」という偽の結果**になり、最後には複製自体がブロックされた
（負の対照さえ ±5.4% 振れた）。

⇒ **両方を cargo に直接ビルドさせる**（`git worktree` ＋ 別 target）。
⇒ **向きを逆にした A/B も取る**（実効果なら符号が逆になって数値が対応する）。
⇒ **絶対値のドリフトを監視する**（セッション中に上がったら環境が壊れている合図）。

取り直した結果:

| 区間 | 結果 |
|---|---|
| B13 全体 | 全ベンチが対照帯内。**有意な変化なし** |
| B13 段階 B 単体 | `bench_method_call` 約 4% 速い / `bottleneck_bench` 約 3.5% 遅い（向きが逆＝コード配置差）|
| B10 段階 2（専用スタック）| 起動 **+0.21 ms（約 1%）**。当初「+0.5ms・有意」と報告したのは**過大** |

この 3 項目は `vm-pitfalls` §1 に追加済み。

### 5-b. コメントに「触れない」と書いて実測で否定された

`deep_copy_value` について「`inst` 自身には触れない」と注記したが**誤り**で、
`borrow_mut()` を握ったまま複製して `RefCell already mutably borrowed` を **3 経路**で踏んだ。
⇒ **「触れない」は測ってから書く。**
